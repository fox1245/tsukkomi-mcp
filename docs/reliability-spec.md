# Session audit reliability (v0.2, updated for 0.6.0)

Source baseline: `ea39649`. Scope: detection and evidence; no action execution or automatic blocking. Rows R1-R7 are the original v0.2 requirements; R1 and R3 were tightened and R8-R10 added in 0.6.0 ([#4](https://github.com/fox1245/tsukkomi-mcp/issues/4), [#5](https://github.com/fox1245/tsukkomi-mcp/issues/5), [#8](https://github.com/fox1245/tsukkomi-mcp/issues/8), [#10](https://github.com/fox1245/tsukkomi-mcp/issues/10)).

| ID | Requirement | Acceptance |
|---|---|---|
| R1 | Lossless incremental JSONL | Both providers retain the first appended event, wait for complete lines, surface malformed lines, and retain long commands. Records appended while a source is being captured are tolerated: they are reported as `unread_bytes`, not as a changed source. |
| R2 | Event identity independent of embedding identity | Repeated calls remain separate, stable events; unchanged/same-content embeddings are reused. Provider/session boundaries are preserved. |
| R3 | Honest verdicts | Rank-only retrieval never causes suspicious/violation. Description-only, empty contracts, incomplete coverage and missing anchors yield unknown. Example rules are opt-in. A growing session is judged as of the captured offset (`judged_through_byte`, `unread_bytes`, `judged_prefix`, `complete=false`); a `must` obligation that rests on absent or failed evidence is unknown while bytes are unread. A rewrite, truncation, replacement or deletion is never growth and stays unknown. `requires_attention` follows the verdict. |
| R4 | Contextual contracts | Source event, provider/session, roles and activation anchor are explicit. A must rule can require matching evidence before each trigger and a linked successful tool result. |
| R5 | Prospective audit | check_action syncs history and checks the proposed call without executing or recording it as an executed event. Returns coverage and contract snapshot. A prerequisite that requires success stays unknown while required history is unread, since a newer failed run may be unread. |
| R6 | Redacted external inputs | Mask before embedding documents and queries; preserve local evidence. No real sessions or live embeddings in tests. |
| R7 | Delivery | Regression tests, original tests, MCP smoke test, wheel build and documented limitations. Integrate reviewed diff into source working tree without moving its branch. |
| R8 | Append-tolerant source capture | A capture hashes the file up to its first-measured length without retaining bytes. Pure growth after that point is accepted if the captured prefix still hashes identically; an overwrite, truncation, replacement or deletion is rejected. `validate()` compares metadata only and never proves content equality. A detected mismatch stays failed. `stat` and `fstat` stamps are compared only within the same API, and an `st_ino` of 0 carries no identity. |
| R9 | One index entry per session id | A second file with the same provider/session id is compared by prefix hash. An identical copy or a strict prefix is reported as an alias and is not reparsed; a continuation is adopted; files that diverge return `ambiguous_session_source` and leave the index unchanged; a rewrite of the same path is reparsed. AGY keeps path identity because its hook receipts bind to the exact path. |
| R10 | Bounded memory and concurrency | Work for one (index, provider, session id) is single-flight. A reparse streams rows to disk and publishes them in batches. Heavy calls are limited by `SELF_DIRECT_MAX_CONCURRENT_CALLS`. Tests assert ratios on small inputs; no large-allocation gate runs in CI. |

The active event schema is separate from legacy v0.1 tables. Old metadata remains available in SQLite for recovery; syncing replays source JSONL into the new schema. Contracts are preserved. The next sync can rebuild a changed/truncated source session. A provider's parser version is recorded per session, and a higher version reparses each session lazily on its next sync. Audits must never call changed, unreadable or unparsed data clean. The only incomplete input that can still be `clean` is pure append, and then only as of the reported offset.

Runtime: operations that touch shared state take a reentrant process lock and a local cross-process file lease. Source hashing, parsing and detached audit evaluation do not hold the lease; see [timeout-fix.md](timeout-fix.md). Refresh in-memory vectors when another process updates them. Embedding errors must not prevent local regex auditing. External API output is validated before cache insertion. Index caches can be repaired by replaying events; they are not the audit source of truth.

Performance gate: 1,000 synthetic events sync + audit under 15 seconds locally, no embedding calls on unchanged second sync, no per-event rewriting of the vector archive. Record observed timings, not a production throughput claim.

Out of scope: a general shell parser, semantic entailment judge, authorization enforcement, human identity attestation, automatic rule extraction, remote deployment. Also out of scope: an atomic file snapshot. A rewrite outside the last 64 KiB of the captured prefix between the final full hash and the publication lock is not detected at that moment; the next sync notices the changed prefix hash and reindexes.
