# Changelog

Notable changes to tsukkomi-mcp (Python package `self_directing_mcp`). Versions follow `pyproject.toml`. Releases before 0.6.0 are not itemized here; see the git history.

## Unreleased

### Changed

- **Lighter command-hook path.** A Claude Code or AGY hook is a fresh Python process for every tool call, so its imports are paid every time. The hooks no longer load NumPy, pydantic-settings, `python-dotenv`, `httpx` (with `certifi`, `idna`, `zstandard`) or `urllib.request`, and `mcp` stays out as before. Interleaved A/B on synthetic data (1 MB session, 10 contracts, 20 runs, median wall): Claude Code `PostToolUse` 189 → 52 ms, `UserPromptSubmit` 185 → 50 ms, `SessionStart` 316 → 208 ms, `PreToolUse` 407 → 281 ms, `Stop` 598 → 410 ms; AGY events 9 to 26 percent faster (their remaining cost is re-parsing the whole transcript on every call). The hook processes' peak RSS drops by 10 to 16 MB.
  - `settings_core` holds the user-TOML `[paths]` source, `CODEX_SESSIONS_DIR`, the defaults, the `resolve_*` accessors and a field table, standard library only and shared with `config.Settings`. `settings_core.load_hook_settings()` reads the same sources with the same precedence and the same rejections as `config.hook_settings()` (never a working-directory `.env`); the hook adapters use it. `config.hook_settings()` remains as the reference implementation, and `tests/test_hook_settings_parity.py` compares the two on about 850 environment and TOML combinations, including inputs both must reject.
  - `self_directing_mcp._runtime.np` is a lazy proxy and still the single loading point: NumPy loads, with one BLAS thread and the environment restored, at the first attribute access. A local-only server never loads it (idle RSS 89 → 79 MB; twelve servers 1073 → 949 MB); a server with an embedder loads it at startup as before.
  - `engine`, `workflow`, `workflow_process`, `workflow_jev`, `embed.embedder` and `neograph_runner` import pydantic `Settings`, `httpx`, `dotenv` and `urllib` where they are used. `workflow_jev.httpx` and `embed.embedder.httpx` remain reachable.
  - `claude_ids` holds the Claude Code session-id grammar, so `UserPromptSubmit`, `PostToolUse` and `PostToolUseFailure` import neither the transcript parser, pydantic nor the engine.
  - Documented exceptions, with measured cost, in [Hook import budget](README.md#hook-import-budget): pydantic (`schemas.py`, about 75 ms) and `neograph_engine` (project rule: audits run through the native graph, about 40 ms).

### Added

- `scripts/bench_hooks.py`: a reproducible benchmark of cold command-hook processes (Claude Code and AGY, through the real entry scripts), concurrent-session bursts, warm calls through the FastMCP dispatcher and the memory of N idle stdio servers, with fixed, documented conditions, JSON and markdown output, an interleaved `--versus` mode and `--check` gating against 1.5 times the targets for what can be met now ("reported, not gated yet" for the rest). The 300 MB session is opt-in. See [Hook cost benchmark](README.md#hook-cost-benchmark).
- `tests/test_hook_import_budget.py` (representative hook judgements must leave `numpy`, `mcp`, `pydantic_settings`, `httpx`, `dotenv` and `zstandard` unloaded and may load only the documented third-party packages), `tests/test_hook_settings_parity.py` and `tests/test_bench_hooks.py`.
- CI: the import budget, settings parity and BLAS thread tests join the Linux regression job, and a `bench` job runs the small-session benchmark with `--check` and uploads its report.

## 0.6.0 - 2026-10-14

Merged in [PR #7](https://github.com/fox1245/tsukkomi-mcp/pull/7) and [PR #11](https://github.com/fox1245/tsukkomi-mcp/pull/11). PR #7 also carried the unmerged commits of the AGY and workflow branch. The Claude Code integration, the shared hook policy, the masking work and AGY parser versions 6 and 7 were added to this release afterwards. Read "Upgrading to 0.6.0" in the [README](README.md) before restarting existing servers: restart every process that shares an index.

### Upgrade-relevant changes

- `neograph-engine` is pinned to `0.14.1` (was `0.12.1`).
- Python before 3.14 now depends on `zstandard>=0.23` to read compressed Codex sessions. Python 3.14+ uses the standard library `compression.zstd`. Without a zstd module, compressed sessions report `zstd_unavailable` and plain sessions are unaffected. Restart existing servers after updating so they can read `.jsonl.zst` rollouts.
- The default index directory is `~/.self_direct_index` (was `.self_direct_index` inside the checkout). Installs that relied on the old default must set `SELF_DIRECT_INDEX_DIR` or TOML `index_dir`; nothing is moved automatically.
- A checkout `.env` is no longer selected as an authoritative key file. Use `SELF_DIRECT_OPENROUTER_API_KEY_FILE` or TOML `openrouter_api_key_file`. A plain `.env` is read only from the server's working directory.
- Parser versions: OMP 2 to 8, Codex 2 to 3, AGY 5 to 7, and the new Claude Code parser at 2. Each indexed session is reparsed lazily on its next sync; existing indexes, vector caches, contracts and checklists are preserved.
- The AGY hook default is now `confirmed_only` (it was `enforced`). Only a confirmed `violation` denies and `suspicious` force-asks; `unknown` passes with a visible warning unless a contract is marked `risk: "high"`. Set `SELF_DIRECT_AGY_ENFORCEMENT=enforced` to keep a strict policy. A `Stop` now continues the agent only for a confirmed `auto_continue` miss, at most once per conversation, and hook errors fail open in every mode (they used to fail closed for `PreToolUse`) ([#1](https://github.com/fox1245/tsukkomi-mcp/issues/1)).
- Sparse (FTS) rows written before 0.6.0 hold raw text. Delete `sparse.sqlite` while the servers are stopped to rebuild it masked from the canonical store (see the [masking contract](SECURITY.md#masking-contract)).

### Added

- **Memory verification CI** (`.github/workflows/memory.yml`, `scripts/verify_memory.py`, `scripts/memory_soak.py`). neograph-engine and sqlite-vector are rebuilt from pinned, digest-verified sources with ASan+UBSan and with TSan, and the whole suite runs against them with the runtime preloaded. Canaries prove each sanitizer reports. LeakSanitizer runs at the end of the pytest session and fails only on direct leaks allocated by neograph or sqlite-vector. A soak drives the MCP tool entry points in one process through steady, growing and churning sessions. First results: no sanitizer reports and no native leaks on the whole suite; no retained-heap, descriptor or thread growth in the soak. See [Memory verification](README.md#memory-verification).
- `tests/test_native_vector_stress.py` (runs with `SQLITE_VECTOR_TEST_PATH`) and `TSUKKOMI_TEST_DENSE_BACKEND=sqlite-vector` to run the suite on the native vector backend.
- `SELF_DIRECT_MAX_CONCURRENT_CALLS` (default 4) bounds concurrently running heavy tool calls ([#5](https://github.com/fox1245/tsukkomi-mcp/issues/5)).
- **Compressed Codex sessions.** Codex CLI 0.156 compresses older rollouts in place to `rollout-<timestamp>-<uuid>.jsonl.zst` (a second `_<uuid>` suffix marks a forked or sub-agent rollout). Discovery, session-id lookup and explicit paths now accept them under the Codex root with the same root, symlink and traversal checks. Byte offsets, anchors and prefix hashes address the decompressed stream, so a plain rollout compressed in place (or decompressed again and appended to) keeps its event ids, anchors and cached vectors, with no reparse, duplicate session or `ambiguous_session_source`; both forms at once follow the duplicate-source rules. A compressed file is an immutable snapshot (no `unread_bytes` once read to its end; a changed file is a rewrite). Decoding streams through a bounded reader: a 54.5 MB synthetic session syncs with the same traced peak (16 MB) as the identical plain file. Each compressed source must be one zstd frame that declares its content size; corrupt, truncated, wrong-size, unsupported and oversized files are explicit errors (`zstd_corrupt`, `zstd_truncated`, `zstd_size_mismatch`, `zstd_unsupported_frame`, `zstd_too_large`, `zstd_unavailable`) that leave the index untouched and make coverage incomplete. `SELF_DIRECT_MAX_DECOMPRESSED_SESSION_BYTES` (default 4 GiB) bounds the declared size. The Codex parser stays at version 3, so nothing is reparsed on upgrade. See [Compressed Codex sessions](README.md#compressed-codex-sessions).
- Coverage fields `judged_through_byte`, `unread_bytes` and `judged_prefix` for audits of growing sessions ([#4](https://github.com/fox1245/tsukkomi-mcp/issues/4)).
- `checklist_conflict` status from `update_checklist` ([#6](https://github.com/fox1245/tsukkomi-mcp/issues/6)).
- Duplicate session sources: `alias_of`, `coverage.indexed_path` and `coverage.requested_path`, the `requested_source_is_prefix_of_indexed` issue and the `ambiguous_session_source` error ([#10](https://github.com/fox1245/tsukkomi-mcp/issues/10)).
- Linux CI job `memory-audit-regressions` with small offline memory, freshness and concurrency tests ([#8](https://github.com/fox1245/tsukkomi-mcp/issues/8)).
- AGY evidence linkage and enforcement with host receipts (part of [#1](https://github.com/fox1245/tsukkomi-mcp/issues/1)) and a first implementation of the approved-workflow layer, the `workflow_*` tools and the `tsukkomi-workflow` command ([#2](https://github.com/fox1245/tsukkomi-mcp/issues/2)). Both issues remain open.
- User path configuration in `~/.config/tsukkomi-mcp/config.toml` (or `SELF_DIRECT_CONFIG_FILE`) and a shared OMP bridge bootstrap (`--omp-bridge`).
- OMP extension tool `tsukkomi_session_context`, which returns the actual persisted OMP session id.
- `CHANGELOG.md`, a project-specific `SECURITY.md` and the MIT `LICENSE` file that the README has always referred to. `pyproject.toml` declares `license = "MIT"` (SPDX expression), which needs `setuptools>=77`; the sdist and the wheel contain the file.
- **Claude Code provider** `claude` (parser version 2) for Claude Code session transcripts and their subagent files. A user turn is only a record stamped `origin.kind == "human"`, a legacy prompt from before origin stamps in a main file, or a human `queued_command` prompt; task notifications, peer and coordinator messages, injected meta messages, compaction summaries, attachments, hook output and a subagent's task prompt are runtime evidence. Unknown shapes stay unsupported and keep coverage incomplete; opaque payloads become placeholders. Subagent files are separate sessions (`<session-uuid>_agent-<agent-id>`). Inherited subagent history, `queued_command` variants, newer attachment types, `plan_mode`, informational system records, `continued-in` metadata and the `scheduled_task_fire` system record (a scheduled task fired; runtime metadata whose `prompt` is validated but never indexed and can neither satisfy nor violate a user-role contract) are accepted. A tool result named by a `read_truncation_notice` never establishes success and, without a visible match, is `unknown` with the reason `truncated_result`. Settings: `SELF_DIRECT_CLAUDE_PROJECTS_DIR` (TOML `claude_projects_dir`). The default root follows `CLAUDE_CONFIG_DIR` (`$CLAUDE_CONFIG_DIR/projects`) when it is set, else `~/.claude/projects` ([docs/claude-installation.md](docs/claude-installation.md)).
- **Claude Code hook adapter** (`scripts/claude_hook.py`) for `SessionStart`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `PostToolUseFailure`, `Stop` and `SubagentStop`, and `scripts/install_claude_hooks.py` (`--print` by default; `--apply` and `--uninstall` on an explicitly named settings file, with a backup only when the file changes, an atomic write and detection of the installer's own handlers). `SELF_DIRECT_CLAUDE_ENFORCEMENT` defaults to `confirmed_only`: `deny` for a confirmed `violation`, `ask` for `suspicious`, no decision otherwise, never an explicit `allow`, because a hook allow would skip Claude Code's own permission prompt. Warnings reach the model at the next `PostToolUse`, `UserPromptSubmit` or `SessionStart`; a `Stop` blocks at most once per session for a confirmed `auto_continue` miss; all output is masked and every internal error fails open with a visible warning and a `hook_health` entry. `docs/claude-hooks.example.json` shows the complete hooks block.
- `SubagentStop` judges the subagent's own transcript but only reports and never blocks, and subagent stops never spend the session's continuation. A global obligation the user set for their own session is not a task the subagent was given. A `PreToolUse` inside a subagent demotes history-dependent `must` findings to `unknown`, because the subagent's history is not in the audited transcript.
- Lifecycle hooks (AGY and Claude Code) build their settings from the environment and the user TOML only (`config.hook_settings()`) and never read a `.env` in the working directory, which is content the audited agent can write. The MCP server still reads `./.env` at the lowest precedence. Hook configuration therefore comes from the hook command's environment (the settings `env` for Claude Code, the hook command for AGY) or the TOML.
- `scripts/install_claude_hooks.py --index-dir /absolute/path` bakes `--index-dir=PATH` into every hook command (a relative path is rejected with exit status 2). The hook entry point and its standard-library fallback set `SELF_DIRECT_INDEX_DIR` from it, overriding the inherited environment, so `hook_health` is recorded in that index.
- Stop flush-lag guard: Claude Code runs `Stop` before the final assistant message is written to the transcript, so a miss of a `message`- or `any`-scoped obligation waits until the host's copy of that message (`last_assistant_message`) appears in the transcript. Misses of `tool_call` and `tool_result` obligations are judged normally.
- Shared hook policy (`hook_policy.py`): one verdict-to-decision table, confirmed-miss selection and Stop checkpoint for AGY and Claude Code, so the hosts differ only in how a decision is expressed. Each host keeps its own state file for its continue budget, warning queue and `hook_health`. A new common judgement fixture feeds one synthetic session through the Codex, OMP, AGY and Claude Code paths and requires identical verdicts.
- Contract fields `risk` (`normal` or `high`), `auto_continue` and `when` (`{"tool_call_regex": ...}`), with four disabled high-risk presets (`preset-no-recursive-delete`, `preset-no-write-outside-workspace`, `preset-no-force-push`, `preset-no-branch-delete`) that are added to the store only when `SELF_DIRECT_SEED_EXAMPLE_CONTRACTS=true` and never re-enabled automatically. The new fields are omitted from stored contracts while at their defaults.
- AGY hook state: bounded `Stop` continuation persisted per conversation, `hook_health` with an `INACTIVE` or `DEGRADED` banner at the next `PreInvocation`, queued warnings for unverified allows, and a standard-library fallback script that records health and honors high-risk contracts after an import failure.
- AGY parser version 6: truncated fields fall back to the same step of the sibling `transcript_full.jsonl` (bounded-memory index, per-record digest); what stays cut keeps its visible text, is marked, and makes dependent verdicts `unknown` with `truncated_<field>` reasons while a visible match still counts. `RUNNING` results are `pending_running`, `ERROR`, `INVALID` and `CANCELED` are never success, and `CHECKPOINT`, `ERROR_MESSAGE` and media records are parsed (media as placeholders). Results from before a conversation's first hook receipt are `legacy_unlinked` (reason `unsupported_legacy`), and coverage gains `receipts_since`, `legacy_unlinked_count`, `result_dependent_complete` and `agy_evidence` counts.
- AGY parser version 7: the Antigravity IDE's typed result steps `RUN_COMMAND`, `VIEW_FILE`, `CODE_ACTION`, `MCP_TOOL` and `LIST_DIRECTORY` are tool results with the evidence rules of `GENERIC` (linked to their call only through a host receipt; `legacy_unlinked` or `native_log_omits_call_id` otherwise; truncated content falls back to `transcript_full.jsonl` or leaves dependent verdicts `unknown` with `truncated_content`; `RUNNING` is pending; `ERROR`, `INVALID` and `CANCELED` are never success). A linked `DONE` `RUN_COMMAND` with host `exit_code` 0 is success evidence, a nonzero `exit_code` is a failure, and an unlinked result is never success; the step type is kept as `result_type`. `CONVERSATION_HISTORY` and `KNOWLEDGE_ARTIFACTS` are runtime metadata. A leading run of NUL bytes in front of an otherwise valid record is stripped and recorded (`host_padding_bytes`, `agy_evidence.host_padded_records`), also in `transcript_full.jsonl` and for hook receipts; every other use of NUL bytes stays a parse error. Any other unknown step type stays an unsupported event.
- Secret masking on every egress path: MCP tool results and errors, hook output, injected context, server logs (a logging filter), crash tracebacks, embedding inputs, search queries, GraphRAG prompts and the sparse index text, with many more patterns (provider tokens, JWTs, private key blocks, URL credentials, `Authorization`, `Cookie` and `Bearer` values, key/value pairs, base64 blobs) and exact masking of the process's own API key (`register_secret`). Contract rule regexes and workflow grants round-trip unmasked ([SECURITY.md](SECURITY.md#masking-contract)).

### Changed

- Source capture streams a SHA-256 over the file up to its first-measured length and keeps no bytes. `validate_prefix()` tolerates pure growth after re-hashing the prefix; `validate()` is metadata only. `stat` and `fstat` stamps are compared within the same API, and an `st_ino` of 0 (some Windows filesystems) skips the inode comparison ([#4](https://github.com/fox1245/tsukkomi-mcp/issues/4), [#5](https://github.com/fox1245/tsukkomi-mcp/issues/5)).
- Audits judge a growing session as of the captured offset and say so in `coverage` and `notes`. `must` obligations that rest on absent or failed evidence become `unknown` while bytes are unread. Rewrites, truncation, replacement and deletion stay `unknown`. `requires_attention` follows the verdict ([#4](https://github.com/fox1245/tsukkomi-mcp/issues/4)).
- `check_action` keeps a proposed action's `requires_success` prerequisites `unknown` while required history is unread ([#8](https://github.com/fox1245/tsukkomi-mcp/issues/8)).
- Memory and concurrency: single-flight per (index, provider, session id), streaming reparse through a disk spool with batched publication, per-session id queries, float32 sync vectors, slimmer audit row loading, and `malloc_trim` on glibc after heavy calls ([#5](https://github.com/fox1245/tsukkomi-mcp/issues/5), [#10](https://github.com/fox1245/tsukkomi-mcp/issues/10)). On a 100 MB synthetic OMP session with 8 concurrent threads, peak RSS fell from 2,304 MB to 193 MB ([PR #7](https://github.com/fox1245/tsukkomi-mcp/pull/7)).
- `audit_status` counts sparse documents from `chunk_rows` instead of scanning the FTS5 table ([#5](https://github.com/fox1245/tsukkomi-mcp/issues/5)).
- Shared-index snapshots and cooperative request deadlines; `index_busy`, `request_deadline`, `request_cancelled` and `operation_timeout` are distinct results ([#3](https://github.com/fox1245/tsukkomi-mcp/issues/3)).
- OMP parser v8 accepts host notices, image placeholders, steering records, `session_init`, `model_usage`, `branch_summary` and `redactedThinking` as runtime records. Only `attribution: "user"` steering is a user turn; agent-attributed user-role messages are runtime text ([#9](https://github.com/fox1245/tsukkomi-mcp/issues/9)).
- A rollout file name that contains two different UUIDs (the `_<uuid>` suffix form) no longer names a session by itself; the `session_meta` header decides. Session lookup by id prefers a plain `.jsonl` over its compressed twin.
- Codex parser v3 accepts `agent_message`, `inter_agent_communication_metadata`, `tool_search_call`/`tool_search_output`, the newer `session_meta` fields and inherited parent headers. `base_instructions`, `dynamic_tools`, account ids and tool lists are never indexed ([PR #11](https://github.com/fox1245/tsukkomi-mcp/pull/11)).
- AGY advisory mode no longer gates approved workflows: in `advisory`, `PreToolUse` allows a mapped completion action with an advisory reason and `Stop` does not hold an incomplete workflow. In the other modes the workflow hold shares the once-per-conversation budget.
- `get_settings()` no longer loads the selected key file into `os.environ`, where subprocesses and native hosts would inherit every variable in a shared file. sqlite-vector auto-detection also checks the setup script's `.native/` default, the sdist ships `CHANGELOG.md` and `SECURITY.md`, and the setup skill no longer suggests a fake embedder as a fallback when a key is missing.
- `when` gates `must` obligations that are checked against a proposed action, and a `not_applicable` finding that late incompleteness turns `unknown` no longer keeps its applicability. Healthy hook-state reads take no write lock, and concurrent continue claims spend the budget exactly once.
- Masking is faster (per-stem rules, static templates and an ASCII mode).
- Tests: symlink tests report a skip with a reason where Windows denies symlink creation (`WinError 1314`, Developer Mode off); the installer quoting and the dotenv JSON fixture are platform-aware.
- OMP history retrieval uses OpenRouter by default; offline mode is the explicit `SELF_DIRECT_LOCAL_ONLY=true`. Session evidence is masked before remote graph extraction, and workflow classification uses the shared OpenRouter key settings.

### Fixed

- The allocator trim after heavy calls now counts the heavy work done since the last trim, not the length of one call. A server that mostly answers short hook checks never had a single call long enough to trim, so freed heap stayed resident; it now trims at most every 5 seconds once 0.5 seconds of heavy work has accumulated. In the soak, live native allocations stay flat as history grows; the remaining RSS growth is allocator-retained memory.
- A local-only process sharing an index that has dense vectors (for example a lifecycle hook installed with `--local-only` next to a server with embeddings) now leaves the vector cleanup of obsolete chunk ids journalled instead of acknowledging it. Before, a reparse in that process removed the ids from the sparse index only, and their vectors stayed orphaned for good. The next sync by a process with the dense index removes them.
- AGY hooks in `advisory` mode no longer deny or continue on an internal exception, in `agy_hooks.main` and in the fallback script.
- Sync no longer fails with `source changed during preparation` when records are appended during capture ([#4](https://github.com/fox1245/tsukkomi-mcp/issues/4)).
- Equal file stamps no longer skip content verification, and a detected mismatch stays failed ([#8](https://github.com/fox1245/tsukkomi-mcp/issues/8)).
- A stale capture can no longer rewind a cursor that another process already published ([PR #7](https://github.com/fox1245/tsukkomi-mcp/pull/7)).
- Unbounded memory growth in long-running servers ([#5](https://github.com/fox1245/tsukkomi-mcp/issues/5)).
- Concurrent `update_checklist` and contract updates no longer fail with stale-preparation errors ([#6](https://github.com/fox1245/tsukkomi-mcp/issues/6)).
- Agent-attributed messages with partial steering metadata were treated as user turns, and payloads of unsupported image and `redactedThinking` blocks were indexed ([#9](https://github.com/fox1245/tsukkomi-mcp/issues/9)).
- Files with the same session id in different folders caused a full reparse on every sync ([#10](https://github.com/fox1245/tsukkomi-mcp/issues/10)).
- Real Codex sessions no longer report most records as unsupported or as parse errors; in a 571-session check, v2 showed unsupported events in 401 sessions and parse errors in 121, and v3 showed none ([PR #11](https://github.com/fox1245/tsukkomi-mcp/pull/11)).

### Known limitations

- Capture and validation are not an atomic snapshot. A rewrite outside the last 64 KiB between the final full hash and the publication lock is accepted at that moment; the next sync reindexes because the cursor's prefix hash no longer matches.
- On Windows `st_ctime` is the creation time, so a same-size rewrite that restores `mtime` is invisible to `stat`; the next sync catches it through the cursor prefix hash.
- `clean` for a growing session means clean as of `judged_through_byte`. Records appended during the audit are judged by the next audit.
- Memory with a live ~310 MB session was not measured before release.
