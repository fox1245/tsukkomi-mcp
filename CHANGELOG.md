# Changelog

Notable changes to tsukkomi-mcp (Python package `self_directing_mcp`). Versions follow `pyproject.toml`. Releases before 0.6.0 are not itemized here; see the git history.

## Unreleased

Source integrity (one scan of the source prefix per request, block digests, a fast path for hook-time checks) and incremental contract audits (a monitor state per contract, so an audit reads only what was appended). Restart every process that shares an index after upgrading (see "Upgrading to 0.6.0" in the [README](README.md): an older process that meets a migrated cursor reindexes that session once).

### Added

- **Host-side GraphRAG extraction.** `graph_next_batch` returns the next batch of session events (complete events, masked as `run_neograph_update` masks them, at most 100 events and 24,000 characters by default so that a result fits what a host lets a tool return; `max_events` and `max_chars` raise that to the 100 and 95,000 that `run_neograph_update` always uses, and a complete result ends with `end_of_batch` as its last key, also when the resident daemon serves it: its `served_by` stamp goes in before the marker) with a versioned `batch_id` (`gb1-<start>-<end>-<digest>`), the extractor instructions, the proposal schema and the allowed relations; `graph_submit_batch` validates and commits the calling agent's extraction. Neither uses the key, calls a model or opens the network, and both work with `SELF_DIRECT_LOCAL_ONLY=true`. A submit recomputes the batch from the index (`batch_changed`), commits in order (`out_of_order`, `stale_batch`; `after_order` on `graph_next_batch` plans batches ahead for parallel extraction), accepts only a proposal of the published shape and size caps whose edges cite events of that very batch, rejects a proposal without edges (`empty_graph_requires_review`, cursor retained) unless `no_graph_facts_reason` records a skip, and is idempotent (the job id is the batch id). The `extractor` label is provenance only and is stored in the job detail. Event text is untrusted data; the batch and the tool descriptions say so, and README "Host-side GraphRAG extraction" covers the restricted-agent setup and the disclosure that extracting with another vendor's model implies.
- `SELF_DIRECT_GRAPH_EXTRACTOR` (`openrouter`, the default, or `host`): `host` makes `run_neograph_update` return `extractor_disabled` without touching the key or the network; the host tools and the manual propose/commit tools are unaffected. An unknown value is an error (`config.Settings`, `settings_core.FIELDS`, the parity tests, the README table and `.env.example`).
- `commit_graph_update(..., through_order=N)` advances the cursor only through event `N` (`invalid_through_order`, nothing stored, unless `N` lies between the first unprocessed event and the last event). `propose_graph_update` and `commit_graph_update` report `covers_through_order`, the position a commit without `through_order` moves the cursor to: the end of the whole session, which is what it always did (the docstrings now say so).
- Tests: `tests/test_graph_host_extraction.py` (loop, masking, lookahead, ordering, tamper and foreign batch ids, evidence outside the batch, caps, empty and skipped batches, conflicts, local-only, the setting, `through_order`, the shared prompt, the parse-count regression); the secret-egress matrix drives both tools in every scenario.
- **Block digests** of the indexed prefix of every plain session file (Codex, OMP, Claude Code, Grok Bot): the SHA-256 of each complete 1 MiB block, the digest of the partial tail block, the newline count and a root, in a new `source_blocks` table of the index metadata (created by a schema migration on first open; no other table is touched). They are built during the capture pass that happens anyway and extended, not recomputed, as the cursor advances. The cursor's `prefix_hash` becomes `blocks1:<root>`; a cursor that still holds a plain SHA-256 migrates in place on its next full request without a reindex. A table that is missing, stale, damaged or for another path is never trusted.
- **Fast source verification for hook-time checks.** `check_action` and `sync_session` accept `verify="fast"` (the Codex `PreToolUse` hook, the Claude Code and AGY hook adapters and the OMP extension pass it). A fast check compares the file identity and size, the partial tail block, the latest `SELF_DIRECT_INTEGRITY_FAST_RECENT_BLOCKS` blocks (default 4) and `SELF_DIRECT_INTEGRITY_FAST_SAMPLE_BLOCKS` random blocks (default 8, drawn fresh for every call) with their stored digests, then parses only the appended bytes. A different inode, a smaller file, an unchanged size with a moved modification time or any mismatching block escalates to a full verification, which reindexes exactly as a whole-prefix hash mismatch did (`source_changed`). `audit_session`, Stop checkpoints and `auto_continue` decisions are always full; so is any fast request whose last full verification is older than `SELF_DIRECT_INTEGRITY_FULL_VERIFY_INTERVAL_SEC` (default 300). AGY and `.jsonl.zst` sources keep full verification.
- **`integrity` object** on `sync_session`, `check_action` and `audit_session` results and in the context a Codex hook emits: `mode` (`full` or `fast`), `full_verified_through_byte`, `full_verified_at`, `source_generation`, `index_generation`, plus `fast_checked` (which blocks were compared) or `full_reason` (why a full scan was done when a fast one was possible, with `verification_lag_sec` for a missed deadline). The `full_verified_*` fields describe a past verification, never the current source. A fast `clean` that rests on a satisfied prerequisite is accepted only for evidence inside the fully verified region (the finding carries `verified_through`); otherwise the request is settled in full (`evidence_beyond_verified_region`). A fast verdict never turns `unknown` or a coverage gap into a satisfied obligation. `auto_continue` requires `integrity.mode == "full"`.
- **Background verification for resident servers** (`integrity_worker.py`, started by the stdio server only): one thread verifies watched sources in full after 2 s of idleness (`SELF_DIRECT_INTEGRITY_BACKGROUND_IDLE_SEC`), starts early enough to beat the 5-minute interval during continuous activity, runs one scan at a time, holds no engine lock while reading, never blocks a request and reports missed deadlines in `audit_status` (`integrity_worker`). Short-lived hook processes never do background work. `SELF_DIRECT_INTEGRITY_BACKGROUND_VERIFY=false` turns it off.
- Settings `SELF_DIRECT_INTEGRITY_FAST_RECENT_BLOCKS`, `SELF_DIRECT_INTEGRITY_FAST_SAMPLE_BLOCKS`, `SELF_DIRECT_INTEGRITY_FULL_VERIFY_INTERVAL_SEC`, `SELF_DIRECT_INTEGRITY_BACKGROUND_VERIFY`, `SELF_DIRECT_INTEGRITY_BACKGROUND_IDLE_SEC` and `SELF_DIRECT_INTEGRITY_BACKGROUND_MAX_SCANS`.
- `scripts/bench_integrity.py`: a synthetic micro-benchmark (default 300 MB) reporting CPU, wall time and SHA-256 passes for the first sync, a nothing-appended and a small-append `check_action` and `audit_session`.
- Tests: pass counting through a process-wide `hashlib.sha256` meter (`tests/test_integrity_passes.py`), block-digest unit tests (`tests/test_source_blocks.py`), a tamper matrix for the fast and the full path (same-size rewrite with the modification time restored, middle block, tail, truncation, replacement by a new inode, growth plus tamper, sampled versus unsampled block) with the time-, event- and background-triggered full verifications that must catch what a fast check missed, and fast-versus-full equivalence on untampered data (`tests/test_integrity_fast_path.py`, `tests/test_integrity_worker.py`).
- **Incremental contract audits.** `audit_session` and `check_action` keep a bounded monitor state per contract in the index metadata and, after a normal append, read and evaluate only the appended events. Findings, verdicts, evidence, notes, coverage (including `judged_through_byte`, `unread_bytes` and every unknown reason) and the NeoGraph stage trace are identical to the full evaluation, which stays the reference and still runs through the native `contract_audit` graph. Every contract kind is summarized: anchors and `applies_from_event_id`, `when`, `must_not` (scopes, roles, `exception_regex`), `must` presence, `before_regex` ordering, `requires_success` (a per-call tracker), Claude Code cut results and AGY truncated fields, pending (`RUNNING`) results, legacy results, host-logged proposals and denials. A state is valid only for its contract revision and content, parser and evaluator version, needs, index generation, cursor path and a commit-log chain from the stored `(byte_offset, prefix_hash, event_count)` to the current cursor; a reindex, rewrite, parser bump, moved source or foreign cursor write rebuilds it. Bounded tables (the `exception_regex` match texts, pending results, blocked proposals, cut results, notice targets) report an overflow, send that contract to the full evaluator and remember it. `SELF_DIRECT_AUDIT_SHADOW_EVERY` (default 16; the default is now `adaptive`, see "Changed" below) also runs the full evaluator on about every Nth audit, after every rebuild and whenever the request has time for it, and compares: on a difference the full result is returned, `incremental.incremental_mismatch` and the `audit_incremental_health` table record it, and that contract stays on full evaluation until the evaluator version changes. `SELF_DIRECT_AUDIT_INCREMENTAL=false` switches the feature off. Results carry an `incremental` report. A state describes the stored events, not how the source was verified, so it is written before the fast-verification gate and is the same under `verify="fast"` and `"full"`; a cursor migration to block digests or a cursor rewritten by an older process rebuilds states keyed to the old digest. Contract patterns run on the time-limited engine: a monitor whose pattern times out is dropped for that run, its contract is judged (unknown, never clean) by the full evaluator, its stored state is deleted and nothing is marked unhealthy; a shadow run whose full evaluation times out keeps the full (unknown) answer and does not count as a mismatch. On a synthetic 305 MB, 225,000-event session the evaluation phase (everything after source verification) of an unchanged `audit_session` fell from about 5.1 s to 2 ms and of `check_action` from about 2.4 s to 2 ms; after 100 appended records it is about 4 ms for both, and after 1,000 about 27 ms and 16 ms. The first audit of a session (or of a changed contract) is a rebuild that costs about as much as an old audit, plus a second full evaluation when its shadow comparison has time to run; see [Incremental audits](README.md#incremental-audits) and `scripts/bench_audit.py`.
- `SELF_DIRECT_AUDIT_INCREMENTAL_MIN_EVENTS` (default 500): a session with fewer stored events is evaluated in full and keeps no monitor state. On short sessions a rebuild plus its shadow comparison cost more than the full evaluation they replace: on the scripted evaluation harness the Codex `Stop` p50 went from 24 ms to 48 ms with state kept for every session.
- `scripts/bench_audit.py`: synthetic large-session benchmark for `audit_session` and `check_action` (unchanged, +100 and +1000 records), optionally against an older source tree, with an answer comparison across trees.
- Store: a commit log and generation counter per session (written in the transaction that publishes events), derived audit-state and health tables, a call-id index (built on first use) and `SessionStore.capture_audit_tail`.
- `scripts/bench_hooks.py`: a reproducible benchmark of cold command-hook processes (Claude Code and AGY, through the real entry scripts), concurrent-session bursts, warm calls through the FastMCP dispatcher and the memory of N idle stdio servers, with fixed, documented conditions, JSON and markdown output, an interleaved `--versus` mode and `--check` gating against 1.5 times the targets for what can be met now ("reported, not gated yet" for the rest). The 300 MB session is opt-in. See [Hook cost benchmark](README.md#hook-cost-benchmark).
- `tests/test_hook_import_budget.py` (representative hook judgements must leave `numpy`, `mcp`, `pydantic_settings`, `httpx`, `dotenv` and `zstandard` unloaded and may load only the documented third-party packages), `tests/test_hook_settings_parity.py` and `tests/test_bench_hooks.py`.
- CI: the import budget, settings parity and BLAS thread tests join the Linux regression job, and a `bench` job runs the small-session benchmark with `--check` and uploads its report.
- **Contract fragility report** (informational, [#15](https://github.com/fox1245/tsukkomi-mcp/issues/15) B4). `upsert_contracts` returns a `fragility` section that lists, per saved `must_not` `regex` (or `must` `before_regex`), the equivalent spellings of a risky action it does not match, drawn from a versioned, deterministic, offline variant library (`resources/contract_variants.json`, version 1.0.0: 10 families, 158 variants and 25 canonical spellings; `audit/variants.py`). A family is reported only when the regex matches one of its canonical spellings. Every entry is an unverified candidate (`verified: false`; none was verified by execution) with its platform, technique and preconditions. The section never blocks or alters a registration, never edits a regex and never changes a verdict. It uses the contract regex engine with its time limits (a slow regex is reported as `regex_timeout`), is bounded (8 spellings per family, 4 families per contract, 20 contracts and 3 s per call, with counts of what was omitted) and is imported only by `upsert_contracts`, never by hook paths. See [Contract fragility report](README.md#contract-fragility-report-informational). Tests: `tests/test_contract_fragility.py`.
- **Resident daemon (experimental, off by default; Linux only).** `SELF_DIRECT_DAEMON=on` makes Claude Code and AGY command hooks and the MCP entry point (`self-directing-mcp`, `--omp-bridge`) thin clients of one per-user process (`python -m self_directing_mcp.daemon`) that runs the same `claude_hooks.run_hook` / `agy_hooks.run_hook` functions and the same FastMCP tool functions, with one engine and one integrity worker per resolved-settings key. `off` (the default) is the unchanged standalone mode; on another platform `on` behaves as `off` and says so once. The flag is added to `config.Settings` and `settings_core.FIELDS` with identical validation (`tests/test_hook_settings_parity.py`).
  - **Security.** A private runtime directory (`$XDG_RUNTIME_DIR/tsukkomi/`, else `~/.cache/tsukkomi/run/`, created 0700 and refused when it is a symlink, has another owner or any other mode), a Unix socket with an `SO_PEERCRED` check on every connection, no TCP, length-prefixed JSON frames capped at 16 MiB, a credential-free environment whitelist and a content-free log. The authentication boundary is the OS user; same-user processes are not isolated from each other.
  - **Failure behaviour.** The hook clients (`scripts/claude_hook.py`, `scripts/agy_hook.py`, `self_directing_mcp/daemon/client.py`) import only the standard library. With the daemon unreachable they start one (budget 0.3 s for `PreToolUse` / `PostToolUse` / `UserPromptSubmit` / `PreInvocation`, 3 s for `Stop` / `SubagentStop` / `SessionStart`) and otherwise fail open with a visible `daemon_unavailable` warning through the existing `fail_open` helpers (`risk: high` contracts that match still `ask`), never importing the engine and never judging in-process; more than 3 starts in 5 minutes stops starting (`crash-loop`). `queue_full`, `version_mismatch`, a dead or silent daemon and an unsafe runtime directory fail open the same way.
  - **Lifecycle.** Single instance by lock file; exit after `SELF_DIRECT_DAEMON_IDLE_EXIT_SEC` (900) idle, or drain-and-exit after a request when RSS exceeds `SELF_DIRECT_DAEMON_MAX_RSS_MB` (400); a newer client drains an older daemon and starts its successor, an older client gets `version_mismatch`; hook and heavy work run on separate thread pools and sessions are bounded (`unknown(queue_full)`).
  - **MCP.** The relay is standard library only (stdio to socket, with reconnect and handshake replay across a daemon restart); the daemon serves one MCP session per connection with `server.mcp`. `server._engine` is now a proxy that resolves a per-connection `ContextVar` and otherwise the module's own engine (created on first use), the heavy-call gate is per engine, `--omp-bridge` validation lives in `server.omp_bridge_settings`, and tool results the daemon serves carry `served_by: "daemon"` (standalone results are unchanged). The console scripts `self-directing-mcp` and `tsukkomi-mcp` now point at `self_directing_mcp.entry:main`.
  - `served_by` for hooks is recorded in the hook state database (`served_by` table), never in the host's hook JSON. `scripts/bench_daemon.py` measures cold hooks through a warm daemon against standalone and idle relays plus one daemon against standalone servers; `tests/daemon/` covers framing, directory checks, peer credentials, bounds, versions, idle exit, the RSS drain, byte-identical hook output, concurrency, every failure mode, the client import budget, MCP parity and an end-of-test and end-of-suite check that no daemon process survives. See [Resident daemon](README.md#resident-daemon-experimental-off-by-default).
- **Journal mode of the authority databases: measured, opt-in, not the default** ([#18](https://github.com/fox1245/tsukkomi-mcp/issues/18) R1). `SELF_DIRECT_SQLITE_JOURNAL=delete|auto` (default `delete`, the rollback journal as before; `config.Settings`, `settings_core.FIELDS` and the parity table validate it identically) selects the journal mode of `meta.sqlite` and `agy-receipts.sqlite`. `auto` uses write-ahead logging only where `journal.choose_journal(path)` positively identifies a local file system (Linux: `os.statvfs` plus `/proc/self/mountinfo`, allow-list ext2/3/4, xfs, btrfs, tmpfs, f2fs, zfs and an overlay whose upper directory resolves to one of those; `9p`/`drvfs`, `nfs*`, `cifs`, `smb*`, `fuse*` and `virtiofs` are denied; anything undeterminable is unknown; Windows: a fixed drive by `GetDriveTypeW`, never UNC, device paths or mapped network drives). **Unknown means DELETE**, which is the old behaviour and not a claim that DELETE is safe there. `synchronous=FULL` is set explicitly on every connection and `NORMAL` is never used for events, cursors or receipts. The mode changes only when a connection is opened, never inside a transaction and never after waiting more than 50 ms; a refused switch (`SQLITE_BUSY`, an older process) keeps the existing mode, is recorded as `pending`, and is retried at the next open and from a resident engine's idle flush; it never fails a request. `audit_status` reports `journal` (policy, per-database mode, wanted mode, reason, `pending`) and `journal_fallback` (the databases on the rollback journal because the file system is `denied:*` or `unknown:*` under `auto`), which is also logged once per directory as `journal_fallback`. `SessionStore.close()` and `SelfDirectEngine.close()` checkpoint the log (`wal_checkpoint(TRUNCATE)`), so a daemon's idle exit does too. `journal.copy_database` / `copy_index_dir` copy through SQLite's online backup API and `journal.remove_database` removes a database with its `-wal`/`-shm`/`-journal` files; `bench_audit.py`, `bench_agy_hooks.py`, `benchmark_large.py` and the AGY equivalence test use them instead of a bare file copy. The AGY receipt/event pairing needed no new marker: the index stores the digest of the receipts each session was derived from with its cursor and every status, sync and judgement compares it with the receipts database (`receipts_not_indexed`); `tests/test_journal_engine.py` pins both partial-commit directions. The hook-state databases and the contracts file are untouched. **Why it is off:** `scripts/bench_commit.py` (new; 300 interleaved samples per cell, ext4, tmpfs and a 9p mount; a `kill -9` test of 50 kills per mode with zero lost acknowledged commits, which is process-kill survival and not power-loss durability) shows write-ahead logging cutting the append transaction of a resident engine by 68 % at p50 (whole operation -56 %; a receipt record -51 %), but in a fresh process per hook, the default install, the transaction is only 20 to 28 % cheaper and the whole operation 10 % slower, because the log is folded into the database when the process closes it; leaving the log in place is worse. Under 25 % on the real default path, so the roundtable's rule keeps it opt-in; it is recommended with `SELF_DIRECT_DAEMON=on`. See [SQLite journal mode, index files and backups](README.md#sqlite-journal-mode-index-files-and-backups) and the [commit benchmark](README.md#commit-benchmark).
- **Public tree cleanup**: the setup skill clones the public repository instead of a private predecessor, the historical timeout report no longer names an unrelated private project, and the Grok Bot fixture session uses a clearly synthetic id.

### Changed

- **Preparing a graph batch costs the batch, not the session.** `run_neograph_update` captured the whole session and parsed every event on every call, then kept at most 100. `SessionStore.event_frames_range` steps over the events before the cursor in the `events_session` index and parses only the batch (and the one event that did not fit); `run_neograph_update` and `graph_next_batch` both read through it with the same limits, masking, `graph_event_too_large` behaviour and `remaining_events` meaning. On a synthetic session of 70,000 events (61 MB of text), no model call: 0.7 to 0.8 s per batch before, 14 to 25 ms after (the deeper the cursor, the more index entries are stepped over), peak memory 365 MB before and 63 MB after; the batches are identical at nine cursor positions. A regression test counts parsed events instead of time (20,000-event session: 100 parsed, 20,000 before).
- The extractor prompt and the proposal schema are one constant each, `neograph_runner.EXTRACT_INSTRUCTIONS` and `PROPOSAL_SCHEMA`, shared by the OpenRouter request and `graph_next_batch`. The schema is byte-identical to the one the request always sent. The prompt is not: it gained one sentence, see the next entry.
- **Node ids, kinds, labels and edge ends must be single-line plain text.** `graphrag.validate_proposal` (so `propose_graph_update`, `commit_graph_update`, `run_neograph_update` and the host tools) and the host tools' shape check reject, by Unicode category, a control character (newline, carriage return, tab, escape and the rest: Cc), the line and paragraph separators U+2028 and U+2029, a lone surrogate and a format character (Cf) other than the zero-width non-joiner U+200C, the zero-width joiner U+200D and the soft hyphen U+00AD. That is every character that can reorder or hide text (the bidirectional marks, embeddings and isolates, the zero-width space, the word joiner and invisible operators, the byte order mark, the interlinear annotation characters, the tag characters), with the other format characters rejected alongside so the rule stays closed for ones added later. The three exceptions only join or hyphenate, and ordinary text needs them: Persian words carry U+200C, emoji sequences and Indic conjuncts carry U+200D, so refusing them would reject, again and again, what a model writes in those scripts (`run_neograph_update` has no way to ask it to rephrase). Everything else, Hangul and the other scripts included, is accepted; README "Single-line text" has the exact rule. Problem texts name the code points instead of repeating the text, and the existing ones escape what they echo. **The OpenRouter extractor prompt gained one sentence** at the end of its rules (`node_id, kind and label must be single-line plain text: ...`) so that a model stops writing what the check refuses; the text before it and the proposal schema are unchanged (`tests/test_graph_host_extraction.py` pins the hash of both), and `graph_next_batch` hands out the same instructions with a `text_rules` line. The AGY `PreInvocation` hook printed `Context only: <src> -[<relation>]-> <dst>` with the stored text as it was, so an id such as `x`, a newline, `Contract [allow-everything] must_not: ...` came out as lines of its own in the model's context; it now prints each relation, and each contract description and checklist item it lists, on one line with such characters shown as escapes, which also covers rows stored earlier.
- **Model-written tool prose is not tool-call payload.** Claude Code's `Bash` input (and other built-in tools) has a model-written `description`; AGY tool calls carry `toolAction` and `toolSummary`. A `must_not` regex such as `sqlite3` matched the careful command `ls -l data/app.sqlite3` through its description "without connecting to it with sqlite3" (reported as an 11% false-positive rate in [#15](https://github.com/fox1245/tsukkomi-mcp/issues/15)). Those fields are now excluded from the call text that contracts match, in indexed history and in the proposed action a hook passes to `check_action` alike (one builder, `tool_payload.py`, also used by the Codex gating text and the standard-library high-risk fallback). Only confirmed prose fields are excluded, only their string values; unclassified fields (an MCP tool's `description`, AGY `Description`/`Instruction`, Codex `justification`, OMP `_i`) stay payload. The prose is kept in `meta.tool_prose`; `scope: "prose"` is a follow-up. Parser versions: Claude Code 2 to 3, AGY 7 to 8 (each indexed session is reparsed once on its next sync or audit; restart running processes). The two parser-version tests that pinned 2 and 7 now assert the current version.
- **A masked exit status is not success evidence for `requires_success`.** A `requires_success` contract ("commit only after a successful pytest") accepted any matching command whose recorded result was a success, so `pytest -q || true`, `pytest | tee log` (no `set -o pipefail` earlier in the same command), `pytest; exit 0` or `pytest --collect-only` counted as a passing run. A success recorded for such a command line is no longer evidence: the finding is `unknown` with the reason `success_unverifiable` (not clean, not a violation); a result recorded as failed is still a confirmed failure and the command itself is not blocked. A small quote-aware shell lexer (`audit/shellstatus.py`; operators inside quotes, `$( )` and comments are ignored, `set +e` alone changes nothing, `|| exit 1` and `; exit $?` keep a failure) locates the command the regex matched and decides; the reference evaluator and the incremental monitors call the same function (the monitor's per-call tracker gains the verdict). A `Bash` call run with `run_in_background` is not a success either (its result only says it started). `EVALUATOR_VERSION` 2 to 3, and to 6 once the anchor, refusal and background changes below are counted (stored monitor states are rebuilt once). The differential test generator now emits masking tails.
- **A contract's `source_event_id` must be a user message; weakening a contract needs one.** An audit now makes a contract whose `source_event_id` resolves to a non-user event (a tool result, runtime text, injected context) `unknown` with the reason `anchor_not_user`, in the reference evaluator and the monitors alike (`applies_from_event_id` may still be any event). `upsert_contracts` rejects such an anchor with an error when the event is already indexed and accepts an unresolvable one (the audit decides); its response reports `anchor_checks`. Disabling a contract (`revoke_contract` now takes `source_event_id`) or replacing it with one that may enforce less (a different regex, an added or changed exception, a narrower scope, roles, `when`, provider or session, dropping `requires_success`, lowering `risk`) needs an anchor that resolves to a user message; without one the change is stored as `pending` (a new key of the contracts file, omitted while empty; shown by `list_contracts`), the previous revision stays active and the response says `NOT APPLIED`. A later anchored upsert or revoke applies it. No origin field was added to the stored contract: `ContractRule` rejects unknown keys, so older processes would refuse the file. The user-message test is each parser's `role == "user"`; Codex cannot distinguish typed prompts from user-role injected context. `EVALUATOR_VERSION` 3 to 4. Existing tests that replaced a regex or revoked a contract without an anchor now pass a user anchor.
- **A refused tool call is a rejected proposal, not an executed violation.** Claude Code records the host's permission decision on the record of the tool result: a top-level `permissionDecision` object beside `toolDenialKind`, with an error result (verified against Claude Code 2.1.299 with a synthetic probe, a `PreToolUse` hook answering `deny` for `Bash`). A `must_not` match in a call whose linked result carries `{"decision": "reject", ...}` (whatever its `source`) or the forms `"deny"` / `{"behavior": "deny"}` is no longer an executed match: it is reported in the new `proposals_rejected` list of the finding (`contract_id`, `event_id`, `call_id`, `reason`, `denied_by` (the decision's `source`, or `host`), `denial_event_id`, `at_byte`; omitted while empty), the verdict comes from the remaining evidence (`clean`, reason `no executed forbidden match ...`, when all matches were refused) and an `exception_regex` sees only what ran. A result that merely says error, an `accept`/`allow`/`ask` decision, or an unknown or missing decision is still an attempt; `toolDenialKind` is not read; an id shared by several calls vouches for none. AGY's denied model proposals (already excluded from attempts) are now listed too. Codex, OMP and Cursor / Grok Bot have no reliable host-recorded denial. The Claude Code and AGY `Stop` notes show rejected proposals on their own line, apart from unverified checks and executed violations. Both evaluators implement it (`runner.rejected_calls`, the monitors' `ClaudeFacts.rejected` and per-rule matching-call table; Claude Code `must_not` audits now keep a call-id index and the shared facts state); the audit-event loader reads `permission_decision` for Claude Code. `EVALUATOR_VERSION` 4 to 5 (and 7 once the recorded decision shape below is counted). No parser change.
- **Format drift makes history absence proofs unknown at the finding level too.** With incomplete coverage other than pure append (an unsupported record, a parse error), the overall verdict was already `unknown`, but a `must_not` with no parsed match and a `before_regex` rule with no parsed trigger still said `clean` in their findings. They are now `unknown` (`incomplete evidence cannot prove the absence of a forbidden match` / `... that no triggering action occurred`); a confirmed violation stays a violation, `judged_prefix` (appended bytes only) behaves as before and a proposed action is judged on its own text. `tests/test_format_drift_coverage.py` locks in the behaviour for Claude Code, Codex and AGY.
- **AGY hooks cost what was appended, not the size of the transcript.** A PreToolUse or PostToolUse hook parsed the whole transcript several times (for the anchor and the completed results of its receipt, again when a sync bound the receipt, and again to index it, because every receipt change reparsed the conversation) and hashed the prefix once more for every linked result, so one hook cost O(size) in Python and a first parse O(linked results x size) in SHA-256. Now: (1) a receipt hashes the file once and parses only the records after a prefix verified against the stored SHA-256 (a per-conversation, per-file ledger in `agy-receipts.sqlite`: `scan_state`, `scan_results`; a cache of a parse, used only after the digest of its prefix was recomputed from the file in the same pass, falling back to the whole-file parse on any doubt, a step the transcript already reached, a repeated result or an error); (2) the sync's capture pass keeps a hash state at every receipt's `prefix_length`, so each anchor (still the plain SHA-256 of the file's bytes; AGY is never verified with block digests or samples) is read from that pass; (3) the index stores with the cursor (`session_receipt_deps`) the digest of the receipt of every result step it parsed and the first receipt, which are the only things the parse reads from receipts, and a receipt change reparses (`reindex_reason: "hook_receipts_changed"`) only when it changed one of those for an indexed result: a receipt for a step with no result yet, the usual `PreToolUse`, is a plain append (an index without stored dependencies reparses once, on its next receipt change); (4) `prepare_bindings` scans only for receipts that are unbound and name the file, reads receipts lazily, and `rows_digest` of unchanged rows is not recomputed; (5) the parser rules out undecodable bytes with `str.isascii` and one regex search instead of a Python loop over every character, and resolves the transcript path once per parse. Receipts, chunks, evidence stats, coverage and verdicts are unchanged (`tests/test_agy_append_equivalence.py` compares an index kept by appends, hooks and syncs with a fresh reindex of the same files and receipts). Measured with `scripts/bench_agy_hooks.py` (synthetic transcripts with a linked receipt per result, one hook per fresh process): at 10 MB a `PreToolUse` hook (receipt and contract check) fell from 20.5 s to 0.51 s and a `PostToolUse` hook (receipt and sync) from 20.4 s to 0.58 s, against 0.38 s and 0.36 s at 0.1 MB; the transcript-dependent part left is two SHA-256 passes and per-receipt work in C. The first hook after an upgrade parses the whole file once. See [AGY hook cost](docs/agy-installation.md#hook-cost-what-a-hook-reads).
- **A request scans the source prefix once.** One `check_action` on a 300 MB session hashed the whole prefix five times (the capture pass and four later re-checks); it now hashes it once, in the capture pass. `validate_prefix()` re-checks file identity, `size >= captured length` and the SHA-256 of the last 64 KiB as streamed during the pass; an unchanged size with a moved modification time is settled by a re-read of the prefix; `validate_prefix(full=True)` is the explicit whole-prefix re-read. If the file grew while it was hashed, the bounded check replaces the second scan. The residual window this documents: a rewrite outside the last 64 KiB that restores size and modification time (or that coincides with growth), made after the capture pass of the same request, is accepted by that request and found by the next full scan.
- A change detected between capture and publication (`SourceChanged`, a `ValueError`) now discards the observation and recaptures in full, at most three times in all, before failing with the same `source changed during preparation` error as before.
- `confirmed_misses` (Stop `auto_continue`) requires `integrity.mode == "full"` on the audit.
- Measured on a synthetic 314.6 MB session (75,000 events; `scripts/bench_integrity.py`): a nothing-appended hook-time `check_action` with prohibition contracts costs 0.035 s CPU (was 1.13 s; SHA-256 passes over the file 0.04, was 5.00), 0.11 s after five appended events (was 1.27 s), and `audit_session` 1.02 s (was 1.69 s; 1.00 pass, was 5.00). With a prerequisite gate the evaluation of the indexed history dominates (0.60 s, of which 0.02 s verifies the source).

### Fixed

- **`commit_graph_update` stored nothing after its first call when it was given no `job_id`.** Every such commit was the global job `adhoc`: the first one, in any session, recorded it as applied and every later one, in any session, answered `already_applied` and stored nothing; the documented `through_order` path was caught by it. A commit without a `job_id` is now named by provider, session, the event order it moves the cursor to (its `through_order`, or the end of the session as it stands: the id is derived after that is resolved) and a digest of the proposal (`adhoc-...`): the identical call again at the same place is `already_applied`, any other commit applies, the same proposal after the session has grown included.
- **A job id recorded for another session counted as an applied job.** The storage-level replay guard looked jobs up by id alone and `record_job` replaced whatever row held the id, so a batch whose id had been recorded by a commit in another session answered `already_applied` and stored nothing, for ever. The guard is now scoped to provider and session: another session's id is `job_id_in_use`, nothing is written and the other row is never overwritten.
- `propose_graph_update` and `commit_graph_update` report `covers_through_order` also when they answer `version_conflict` or `evidence_conflict`.
- **Lookups of stored events by id no longer scan the whole session.** `SessionStore.live_ids` and `capture_evidence(history=False, anchors=...)` select from `session_events` by `provider`, `session_id` and a list of event ids. Without table statistics SQLite chose the two equalities over the primary key, so every 500-id batch read the entire session and a derived pass (the search index that `sync_session` and `search_history` build) cost the square of the session size. The equalities are now written `+provider=? AND +session_id=?`, which keeps the planner on the key. The commit of an append asks the same question for the ids it brings, so a large append to a large session paid it too. On synthetic Linux sessions the derived pass over 90,000 events went from 29.3 s to 7.1 s (profiled) and over 150,000 events from 64.2 s to 7.7 s, and appending 100,000 events to an indexed session of 100,000 from 12.7 s to 3.4 s. Appends of a few events were never affected (SQLite already used the key for short lists). `tests/test_event_id_lookups.py` pins the query plan.

Without a zstd module, compressed sessions report `zstd_unavailable` and plain sessions are unaffected. Restart existing servers after updating so they can read `.jsonl.zst` rollouts.
- The default index directory is `~/.self_direct_index` (was `.self_direct_index` inside the checkout). Installs that relied on the old default must set `SELF_DIRECT_INDEX_DIR` or TOML `index_dir`; nothing is moved automatically.
- A checkout `.env` is no longer selected as an authoritative key file. Use `SELF_DIRECT_OPENROUTER_API_KEY_FILE` or TOML `openrouter_api_key_file`. A plain `.env` is read only from the server's working directory.
- Parser versions: OMP 2 to 8, Codex 2 to 3, AGY 5 to 7, and the new Claude Code parser at 2. Each indexed session is reparsed lazily on its next sync; existing indexes, vector caches, contracts and checklists are preserved.
- The AGY hook default is now `confirmed_only` (it was `enforced`). Only a confirmed `violation` denies and `suspicious` force-asks; `unknown` passes with a visible warning unless a contract is marked `risk: "high"`. Set `SELF_DIRECT_AGY_ENFORCEMENT=enforced` to keep a strict policy. A `Stop` now continues the agent only for a confirmed `auto_continue` miss, at most once per conversation, and hook errors fail open in every mode (they used to fail closed for `PreToolUse`) ([#1](https://github.com/fox1245/tsukkomi-mcp/issues/1)).
- Sparse (FTS) rows written before 0.6.0 hold raw text. Delete `sparse.sqlite` while the servers are stopped to rebuild it masked from the canonical store (see the [masking contract](SECURITY.md#masking-contract)).

### Added

Canaries prove each sanitizer reports. LeakSanitizer runs at the end of the pytest session and fails only on direct leaks allocated by neograph or sqlite-vector. A soak drives the MCP tool entry points in one process through steady, growing and churning sessions. First results: no sanitizer reports and no native leaks on the whole suite; no retained-heap, descriptor or thread growth in the soak. See [Memory verification](README.md#memory-verification).

- **Compressed Codex sessions.** Codex CLI 0.156 compresses older rollouts in place to `rollout-<timestamp>-<uuid>.jsonl.zst` (a second `_<uuid>` suffix marks a forked or sub-agent rollout). Discovery, session-id lookup and explicit paths now accept them under the Codex root with the same root, symlink and traversal checks. Byte offsets, anchors and prefix hashes address the decompressed stream, so a plain rollout compressed in place (or decompressed again and appended to) keeps its event ids, anchors and cached vectors, with no reparse, duplicate session or `ambiguous_session_source`; both forms at once follow the duplicate-source rules. A compressed file is an immutable snapshot (no `unread_bytes` once read to its end; a changed file is a rewrite). Decoding streams through a bounded reader: a 54.5 MB synthetic session syncs with the same traced peak (16 MB) as the identical plain file. Each compressed source must be one zstd frame that declares its content size; corrupt, truncated, wrong-size, unsupported and oversized files are explicit errors (`zstd_corrupt`, `zstd_truncated`, `zstd_size_mismatch`, `zstd_unsupported_frame`, `zstd_too_large`, `zstd_unavailable`) that leave the index untouched and make coverage incomplete. `SELF_DIRECT_MAX_DECOMPRESSED_SESSION_BYTES` (default 4 GiB) bounds the declared size. The Codex parser stays at version 3, so nothing is reparsed on upgrade. See [Compressed Codex sessions](README.md#compressed-codex-sessions).

Both issues remain open.

Results from before a conversation's first hook receipt are `legacy_unlinked` (reason `unsupported_legacy`), and coverage gains `receipts_since`, `legacy_unlinked_count`, `result_dependent_complete` and `agy_evidence` counts.

### Changed

- Source capture streams a SHA-256 over the file up to its first-measured length and keeps no bytes. `validate_prefix()` tolerates pure growth after re-hashing the prefix; `validate()` is metadata only. `stat` and `fstat` stamps are compared within the same API, and an `st_ino` of 0 (some Windows filesystems) skips the inode comparison ([#4](https://github.com/fox1245/tsukkomi-mcp/issues/4), [#5](https://github.com/fox1245/tsukkomi-mcp/issues/5)).
- Audits judge a growing session as of the captured offset and say so in `coverage` and `notes`. `must` obligations that rest on absent or failed evidence become `unknown` while bytes are unread. Rewrites, truncation, replacement and deletion stay `unknown`. `requires_attention` follows the verdict ([#4](https://github.com/fox1245/tsukkomi-mcp/issues/4)).
- `check_action` keeps a proposed action's `requires_success` prerequisites `unknown` while required history is unread ([#8](https://github.com/fox1245/tsukkomi-mcp/issues/8)).
- Memory and concurrency: single-flight per (index, provider, session id), streaming reparse through a disk spool with batched publication, per-session id queries, float32 sync vectors, slimmer audit row loading, and `malloc_trim` on glibc after heavy calls ([#5](https://github.com/fox1245/tsukkomi-mcp/issues/5), [#10](https://github.com/fox1245/tsukkomi-mcp/issues/10)). On a 100 MB synthetic OMP session with 8 concurrent threads, peak RSS fell from 2,304 MB to 193 MB ([PR #7](https://github.com/fox1245/tsukkomi-mcp/pull/7)).
- `audit_status` counts sparse documents from `chunk_rows` instead of scanning the FTS5 table ([#5](https://github.com/fox1245/tsukkomi-mcp/issues/5)).
- Shared-index snapshots and cooperative request deadlines; `index_busy`, `request_deadline`, `request_cancelled` and `operation_timeout` are distinct results ([#3](https://github.com/fox1245/tsukkomi-mcp/issues/3)).
- OMP parser v8 accepts host notices, image placeholders, steering records, `session_init`, `model_usage`, `branch_summary` and `redactedThinking` as runtime records. Only `attribution: "user"` steering is a user turn; agent-attributed user-role messages are runtime text ([#9](https://github.com/fox1245/tsukkomi-mcp/issues/9)).
- A rollout file name that contains two different UUIDs (the `_<uuid>` suffix form) no longer names a session by itself; the `session_meta` header decides. Session lookup by id prefers a plain `.jsonl` over its compressed twin.
- Codex parser v3 accepts `agent_message`, `inter_agent_communication_metadata`, `tool_search_call`/`tool_search_output`, the newer `session_meta` fields and inherited parent headers. `base_instructions`, `dynamic_tools`, account ids and tool lists are never indexed ([PR #11](https://github.com/fox1245/tsukkomi-mcp/pull/11)).
- AGY advisory mode no longer gates approved workflows: in `advisory`, `PreToolUse` allows a mapped completion action with an advisory reason and `Stop` does not hold an incomplete workflow. In the other modes the workflow hold shares the once-per-conversation budget.
- `get_settings()` no longer loads the selected key file into `os.environ`, where subprocesses and native hosts would inherit every variable in a shared file. sqlite-vector auto-detection also checks the setup script's `.native/` default, the sdist ships `CHANGELOG.md` and `SECURITY.md`, and the setup skill no longer suggests a fake embedder as a fallback when a key is missing.
- `when` gates `must` obligations that are checked against a proposed action, and a `not_applicable` finding that late incompleteness turns `unknown` no longer keeps its applicability. Healthy hook-state reads take no write lock, and concurrent continue claims spend the budget exactly once.
- Masking is faster (per-stem rules, static templates and an ASCII mode).
- Tests: symlink tests report a skip with a reason where Windows denies symlink creation (`WinError 1314`, Developer Mode off); the installer quoting and the dotenv JSON fixture are platform-aware.
- OMP history retrieval uses OpenRouter by default; offline mode is the explicit `SELF_DIRECT_LOCAL_ONLY=true`. Session evidence is masked before remote graph extraction, and workflow classification uses the shared OpenRouter key settings.

### Fixed

- Contract regexes run with a time limit (`regex` engine, new dependency): 0.25 s per search, 2 s per contract per evaluation. A pathological pattern used to backtrack for minutes, past the audit deadline and a host's hook timeout, after which the host proceeded with the call. Such a contract is now `unknown` (`regex_timeout`); `search_history` regex queries report the limit instead of partial results.
- Codex `PreToolUse` no longer reports an empty-findings `unknown` when no contract applies to the proposed action (`action_scope: not_applicable`), matching the AGY and Claude Code adapters.
- Masking now covers common credential names it missed: `*_PASS`, `*_PWD`, `PASSPHRASE`, `*_KEY`, `*_KEY_ID`, `*_SALT`, `PEPPER`, `*_AUTH`.
- `upsert_contracts` rejects a high-risk `must_not` without a regex (it would ask on every tool call) and validates `exception_regex`.
- The allocator trim after heavy calls now counts the heavy work done since the last trim, not the length of one call. A server that mostly answers short hook checks never had a single call long enough to trim, so freed heap stayed resident; it now trims at most every 5 seconds once 0.5 seconds of heavy work has accumulated. In the soak, live native allocations stay flat as history grows; the remaining RSS growth is allocator-retained memory.
- A local-only process sharing an index that has dense vectors (for example a lifecycle hook installed with `--local-only` next to a server with embeddings) now leaves the vector cleanup of obsolete chunk ids journalled instead of acknowledging it. Before, a reparse in that process removed the ids from the sparse index only, and their vectors stayed orphaned for good. The next sync by a process with the dense index removes them.
- AGY hooks in `advisory` mode no longer deny or continue on an internal exception, in `agy_hooks.main` and in the fallback script.
- Sync no longer fails with `source changed during preparation` when records are appended during capture ([#4](https://github.com/fox1245/tsukkomi-mcp/issues/4)).
- Equal file stamps no longer skip content verification, and a detected mismatch stays failed ([#8](https://github.com/fox1245/tsukkomi-mcp/issues/8)).
- A stale capture can no longer rewind a cursor that another process already published ([PR #7](https://github.com/fox1245/tsukkomi-mcp/pull/7)).
- Unbounded memory growth in long-running servers ([#5](https://github.com/fox1245/tsukkomi-mcp/issues/5)).
- Concurrent `update_checklist` and contract updates no longer fail with stale-preparation errors ([#6](https://github.com/fox1245/tsukkomi-mcp/issues/6)).
- Agent-attributed messages with partial steering metadata were treated as user turns, and payloads of unsupported image and `redactedThinking` blocks were indexed ([#9](https://github.com/fox1245/tsukkomi-mcp/issues/9)).
- Files with the same session id in different folders caused a full reparse on every sync ([#10](https://github.com/fox1245/tsukkomi-mcp/issues/10)).
- Real Codex sessions no longer report most records as unsupported or as parse errors; in a 571-session check, v2 showed unsupported events in 401 sessions and parse errors in 121, and v3 showed none ([PR #11](https://github.com/fox1245/tsukkomi-mcp/pull/11)).

### Known limitations

- Capture and validation are not an atomic snapshot. A rewrite outside the last 64 KiB between the final full hash and the publication lock is accepted at that moment; the next sync reindexes because the cursor's prefix hash no longer matches.
- On Windows `st_ctime` is the creation time, so a same-size rewrite that restores `mtime` is invisible to `stat`; the next sync catches it through the cursor prefix hash.
- `clean` for a growing session means clean as of `judged_through_byte`. Records appended during the audit are judged by the next audit.
- Memory with a live ~310 MB session was not measured before release.
